# OpenIDEA IPC inventory

Generated by [scripts/openidea-ipc.py](scripts/openidea-ipc.py) from the
`third_party/openidea` submodule (bf36cc08019a1be78c151245c67dcd872a9c37b5), not edited by hand. Rerun it after
every submodule bump; `scripts/openidea-ipc.py --check` fails when this file
is stale.

OpenIDEA is the product specification, so this is the list of what a GoIDEA
frontend must eventually reach. The desktop shell registers **668 IPC
commands**; `openidea-server --stdio` answers **476** of them. The rest are
either desktop-shell work (windows, menus, dialogs, clipboard) that a native
Go frontend implements itself, or host logic that is not yet exposed over
stdio and needs an OpenIDEA change before GoIDEA can call it.

## Protocol

JSON-RPC 2.0 over `Content-Length` framing. The server answers `initialize`
(protocol 2), `commands` (this list) and `invoke {window, cmd, args}`.
Streaming arguments are `{"$channel": id}`; the server sends `channel`
notifications, `event` notifications for a window's `IdeEvent`s, and
`plugin` / `plugin_secret` for remote code plugins. GoIDEA's client side is
described in [RPC_PROTOCOL.md](RPC_PROTOCOL.md).

- **desktop** — a native Go frontend implements it (window, menu, dialog,

## What this means for GoIDEA

476 remote commands are available today; GoIDEA uses 104. The parity work is
first to cover the remote surface OpenIDEA's own frontend uses, then to move
`shared-op`/`host`/`crate` commands onto stdio through the OpenIDEA fork
(a submodule bump and a server release), and to implement `desktop` commands
natively in Go. A feature is not ported because a similar Mayoi one exists:
it is ported when the OpenIDEA interaction behind it works in GoIDEA.

Local-only kinds: 56 crate, 114 desktop, 20 host, 4 shared-op.

The gaps that need OpenIDEA work are the 80 `shared-op`, `host` and `crate`
commands above, in that order: the first already have an `ops`
implementation, the second work against the host, and the third must move
out of the Tauri shell first.
